# 视觉索引 VisionIndex

**库里几千张截图、扫描件、拍照笔记里的字,今天在全局搜索里等于不存在。**

视觉索引用你**已经登录的 Forsion 视觉链路**逐张把图里的字读出来,写成**可见目录里的纯 Markdown
sidecar**。于是宿主的全局搜索直接命中图里的文字,并能从命中处一键反查回原图。

它**不自带 OCR 引擎**(与「不自带 ASR」同精神):不打包 Tesseract/PaddleOCR、不接第三方 OCR API、
不要第二个 key。浏览器端的 Tesseract 打不过真实扫描件与中文,本机视觉能力打得过。

## 它是怎么工作的

1. **你圈定目录** —— 勾选装图片的文件夹(如 `Attachments`)。刻意**不做开箱扫全库**:识别烧的是你自己
   的额度,必须你点头。
2. **预算闸先说话** —— 「本次将识别 **N** 张,预估约 **X**」。超出单次上限会明说「已按上限截到 N 张,
   可多次运行」。
3. **串行开跑,随时可停** —— 每张图一次独立的引擎 run(每张一枚新会话:图片会被物化进上下文,复用会话
   = token 爆炸)。**每张读完立刻落盘**,所以「停止」= 已完成的全部作数,再点开始就从剩下的接着跑。
4. **产物即笔记** —— 一张图一份 sidecar,普普通通的 Markdown,宿主全局搜索天然吃得到。

## 产物落在哪

工作文件夹 `W` = 插件详情页的「工作文件夹」设置(默认 `视觉索引`)。

```
视觉索引/
├── Index/                                   ← 识别正文,一图一份,**机器所有**
│   └── Attachments/2026/会议白板 1.png.md
├── Notes/                                   ← 你「转正式笔记」转出来的,**你所有**
│   └── 会议白板 1-2026-08-14.md
└── .visionindex/index.json                  ← 派生状态缓存,**绝不存正文**
```

sidecar 长这样:

```markdown
---
visionindex: 1
source: Attachments/2026/会议白板 1.png
fp: 3f2a91c7
lang: zh
kind: screenshot
chars: 412
extractedAt: 2026-08-14T02:31:07.000Z
---

# 会议白板 1.png

![[Attachments/2026/会议白板 1.png]]

Q3 目标对齐
1. 插件生态:8 月上五个成熟包
```

三条设计上的定死:

- **路径保留原后缀再追加 `.md`**(`a.png` → `Index/a.png.md`):剥掉尾部 `.md` 即还原源路径,不需要任何
  映射表,`a.png` 与 `a.jpg` 也不会撞。
- **`source` 是反查原图的唯一指针**。前端一律读它,不从文件名反推。
- **正文开头内嵌 `![[原图]]`**:在笔记里「看到文字就能看到原图」天然成立。

**红线两条(改代码前先读)**:manifest 绝不声明 `fileExtensions`、绝不认领自定义文件类型 —— 那会让主
进程把 sidecar 排出页面列表,全局搜索就搜不到它,本插件的全部价值当场作废;`.visionindex/` 里也绝不
出现识别正文,连摘要都不行,理由同上。

## 幂等与自愈

| 情形 | 行为 |
|---|---|
| sidecar 已存在 | 跳过(不重识别、不重写) |
| 缓存记 `empty` / `promoted` / `skipped` | 跳过 |
| 缓存记 `failed` | 默认跳过;打开设置「重扫时重试失败的图」才重排队 |
| 你删掉了 sidecar | 下次扫描自动重识别(**自愈**,这是删除的正确语义) |
| 点单条「重新识别」 | 忽略上表,重跑并**整文件覆写** |

`.visionindex/index.json` 是**纯派生**的:它的正当性只有一条 —— 记住那些「没有产出 sidecar」的图。
有 sidecar 的图靠 sidecar 自己说话,所以缓存删掉、烂掉、手改坏,最坏也只是重跑那几张,**永远不会丢
你的数据**。

队列视图里的「重建缓存」按钮**是合并,不是覆写**:`ok` 那一半仅凭库里现有的 sidecar 全量重算,
而 `empty` / `failed` / `promoted` 这些「没有产出 sidecar」的状态一律原样留住 —— 它们的信息在
`listPages()` 里根本不存在,重建时抹掉就意味着已知无文字的图下次全部重烧一遍你的额度、已转正的图
被重新识别并重新长出 sidecar。

## 出错时会发生什么

- **还没登录 / 连不上引擎 → 拦在开跑前**:队列视图先弹「还没连上 Forsion 引擎」横幅,一张都不发出去。
- **单张失败不中断整批**:记进缓存、界面标红(带人话失败码,如「图片超过 5MB」),继续下一张。
- **连续 3 张同码失败 → 自动停批**并弹 error 提示。引擎坏了就别烧 50 张的钱。
- **与引擎断链(HTTP / SSE)→ 整批停,但当前这张一个字都不落账**:它根本没被读过,记 `failed` 就意味着
  「网络恢复之后它再也不会被扫」,与提示语「已读完的全部保留,可接着跑」直接矛盾。不落账 = 它仍在待识别
  队列里,下次续跑自然轮到它。这条和上一条是分开的:一次断链不该把剩下 49 张全烧成 failed。
- **「解析失败」与「空结果」是两种东西**,插件从不合并它们:模型没按格式回复 = `failed`(和上表一致:
  **默认跳过**,打开「重扫时重试失败的图」才会重排队);围栏在但内容为空 = `empty`(这张图真没字,
  **不写 sidecar**,也不再重复烧)。

## sidecar 归机器所有 —— 想长期编辑请先「转正式笔记」

**`Index/` 下的 sidecar 会被重扫整文件覆盖**,不做哨兵分区、不保留手改。想把某段文字变成自己的东西,
点「转正式笔记」:内容(不带插件 frontmatter)转到 `Notes/<源文件名>-<日期>.md`,附一行 `> 来自
[[原图]]`;转出后这张图记 `promoted`,**永不再被扫描触碰**。

## 验证收录:把论证做成可点的证明

「识别结果」视图每条都有**验证收录**按钮:抓本条正文里 12-20 字的一小段,去问宿主的全局搜索,命中该
sidecar 就打绿标「全局搜索可命中」。这是本插件立项论证的可点版本,不是装饰。

## 枚举不到文件时(降级阶梯)

队列视图的状态横幅一共四种,按下表**从上往下**取第一条命中的(没登录时后面三条全是白忙:让 Agent 扫库
要引擎,手动补录跑的也是同一条识别管线):

| 情况 | 界面行为 |
|---|---|
| 还没登录 / 连不上引擎 | 横幅「还没连上 Forsion 引擎」+ 指路设置;开跑前就拦住,一张都不发 |
| 宿主给得出文件清单 + 库绝对路径 | 全功能:目录圈定 → 预算闸 → 批量识别 |
| 清单为空(没打开库 / 网页端) | 横幅说清缺什么,给「让 Agent 扫库」按钮:一次 host run 只用 `glob_files` 列图片,结果过同一条管线 |
| 取不到库绝对路径 | 指令改发**库内相对路径**,并让 Agent 用它系统提示里已有的库路径解析;仍不行再去设置里手填 |
| 旧宿主没有枚举接口 | 横幅 + 「手动补录一张」:输一条库内相对路径,走同一条识别管线(宿主连输入框接口都没有时这个按钮**不画出来** —— 画一个点了没反应的更糟) |

## 支持范围(以及**明确不做**什么)

**收**:`.png` `.jpg` `.jpeg` `.gif` `.webp` `.bmp`,单张 ≤ 5MB(与引擎 `VIEW_IMAGE_MAX_BYTES` 同口径)。

- **不做开箱扫全库** —— 必须你圈定目录才能开跑。
- **不自带 OCR 引擎**(长期否决区)—— 不打包 tesseract/PaddleOCR,不接第三方 OCR API,不要第二个 key。
  视觉能力全部来自你已登录的宿主链路,**模型由引擎自动选,插件永不选模型、也不提模型名**。
- **不碰宿主 PDF 批注** —— `.pdf` 一律不入队;PDF 有引擎侧 `read_document` 与宿主自己的批注管线。
- **不支持 `.svg` / `.heic` / `.tiff`** —— 引擎不收这些格式,也不做转码兜底。
- **不做移动端** —— 依赖 `execMode:'host'` 的本机文件工具。
- **不做内容变更自动重识别** —— UI 层的 `readFile` 只吐 UTF-8 文本、`listFiles` 不给 size/mtime,
  所以 `fp` 如实叫「指纹」(源路径的哈希)**而不是内容哈希**;图片内容变了插件察觉不到,只能你手动点
  「重新识别」。接缝到不了的地方,不吹。
- **不做手写体/公式专项优化**、不做版面还原(表格/多栏一律按阅读顺序平铺)。
- **不做「截图收件箱」/ 发票凭证字段抽取**(首版刻意推迟),不做发票真伪核验。
- **不做翻译** —— 识别出的文字永远保持原语言,界面切中英文不影响你的数据。

## 数据流向

图片路径与识别出的文字,只在**你本机**与**你自己登录的 Forsion 后端**之间流动,不经任何第三方服务;
产物全部落在你的笔记库里。笔记库的绝对路径是敏感信息(可能含用户名、组织目录、云盘路径),插件只在内
存里把它拼进给 Agent 的指令,**不持久化、不写进任何产物文件、不上报**。

## 双语说明

界面中英双语,跟随宿主设置里的语言实时切换(视图不重挂也会变)。两点如实说明:

- **命令面板 / 设置页的标题要重启才跟上**:`registerCommand.title` / `registerView.title` /
  `registerSetting.label` 在宿主侧目前是**注册时的单字符串**,没有运行时重解析。插件**刻意不**为它做
  重注册或 teardown 自重来 —— 那会打断正在跑的识别队列。
- **有几样东西永远不翻译**:识别出的正文(它是你库里的字)、sidecar 的 frontmatter 键名与值、
  `.visionindex/index.json` 的键与状态码、源文件路径、工作文件夹默认名「视觉索引」与 `Index/`
  `Notes/` 子目录名 —— 切语言绝不能让你像换了个数据目录。

## 旧宿主兼容

07-18 之后的 ctx 面一律可选链,缺席时优雅降级而不是抛错:没有 `registerView` 就只留命令;没有
`getLocale` 回退中文;没有 `registerStatusItem` 就不占状态栏;没有 `listFiles`/`vaultRoot` 走上面的
降级阶梯;没有 `notify` 回退 `ctx.app.notify`。⚠️ 注意枚举接缝的语义是**「方法在、结果空」**(没有活
动库 / 网页端一律给空数组而不是抛错),所以插件把空枚举当成一等状态来渲染,而不是当异常。

## 自检与仪器

```bash
node check.mjs          # 契约层:mock ctx 装载 main.js,纯函数向量 + 数据契约往返 + XSS + 双语 + 四时区
```

```bash
# 立项闸仪器(调试铁律 5:仪器留在仓里,下次从跑脚本开始)
node probe.mjs --backend http://127.0.0.1:<桌面端本机引擎端口> --image /绝对/路径/图.png
node probe.mjs --rel Attachments/2026/board.png     # 顺带验「相对路径 + 系统提示解析」那一档
```

`probe.mjs` 问的是唯一一个前提问题:**一次真实 host run 能不能用 `view_image` 读出图里的字?**
它经 `__VISIONINDEX_TEST__` 钩子取插件真身的 `buildExtractMessage` —— probe 里绝不另写一份提示词,
否则测的就不是真管线。token 优先 `--token`,缺省时在**进程内**读 `~/.forsion-dev/auth.json`,不打印
不落盘。

真机 UIUX 门禁(在 `Forsion-Genesis/desktop` 下跑):

```bash
node scripts/plugin-view.e2e.cjs <本插件目录> --expect-views queue,results \
     --expect-commands visionindex-open,visionindex-scan
```

## 安装

```bash
sh install.sh          # → ~/.forsion-dev/plugins/visionindex(dev)
sh install.sh prod     # → ~/.forsion/plugins/visionindex
```

重开 Forsion 后:命令面板「视觉索引:打开」,或工作台切到「视觉索引」Space(左队列 + 主结果 + 右对话)。
